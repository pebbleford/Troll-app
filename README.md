# 😈 Troll Remote

Prank your friend while they play on your PC, using your iPad as the remote.
Jumpscares, creepy sounds, fake crashes, spiders crawling over the screen, and
the PC talking to them out loud.

- **On the PC:** a small app sits invisibly on top of the game. Effects appear
  over the game, and clicks still go through to it, so your friend can keep playing.
- **On the iPad:** a web page with big buttons. There is nothing to install, just scan a QR code.

## Setup (Windows)

1. Install **Node.js LTS** from <https://nodejs.org> (one time only).
2. Get the project. For **automatic updates**, install [Git](https://git-scm.com)
   and run `git clone https://github.com/pebbleford/Troll-app` (this lets the app
   update itself). Or, the no-Git way: green **Code** button → **Download ZIP** and
   unzip it (updates then just notify you instead of installing themselves).
3. Double-click **`start.bat`**. The first run takes a minute while it installs.
4. If Windows Firewall asks, click **Allow access** (Private networks). The iPad
   can't connect without this.
5. A window with a QR code opens. Scan it with the iPad camera (same Wi-Fi as the PC).
6. The first time, it asks if it should **start automatically when the PC turns on** —
   say yes so it's ready before your friend sits down. (You can change this any time
   with the checkbox in the window, or in the tray menu.)
7. Click **Hide to tray**. The app keeps running in the little icon at the
   bottom-right (the system tray) — click that icon any time to open it again.
   It doesn't show up in the taskbar, only the tray.

**No black console window:** after the first run, launch it with
**`start-hidden.vbs`** (double-click) instead of `start.bat` — it starts the app
with no CMD window at all. (Use `start.bat` the first time so you can see it
install, and later if you ever need to see error messages.)

Mac/Linux: run `./start.sh` instead.

Tip: in Safari, tap **Share → Add to Home Screen** to put the remote on your iPad's
home screen like an app. You'll need to enter the 6-letter code (or sign in) once.

### Custom jumpscares & real sounds

The built-in sounds are generated by the app, so some are more "video-gamey"
than real. **To use actual recordings** (real screams, memes, whatever), add
your own sound files — the app plays any `mp3`/`wav`/`ogg`/`m4a`:

1. Grab a free sound (e.g. from pixabay.com, mixkit.co, or freesound.org — no
   account needed for the first two) on your iPad or PC.
2. On the iPad, tap **Upload a file** (or drop it in the `media` folder on the PC).
3. Tap the uploaded sound → **Use this as a soundboard button** → pick which
   button it should become (e.g. **Scream**, or the **Jumpscare scream**).

That button now plays your real sound, with a little **🎵 yours** badge. Pick
**Jumpscare scream** to make the big jumpscare use your sound too. (Deleting the
file puts the original built-in sound back.)

You can also tap an uploaded file to:

- use a **picture** as a jumpscare — and optionally pick one of your uploaded
  **sounds** to play with it instead of the built-in scream;
- just pop a picture up on screen;
- play a sound or a full-screen video.

### 🎤 Talk through their mic

Make the PC "speak" out of its **microphone**, so your friend's game or Discord
voice chat hears a message as if it came from them. Windows won't let an app feed
the real mic directly, so this uses a free **virtual audio cable**:

1. Install **VB-CABLE** (free): <https://vb-audio.com/Cable/> → download, unzip,
   right-click the installer → **Run as administrator**, then reboot. This adds a
   "CABLE Input" and "CABLE Output" device.
2. In the Troll Remote window → **🎤 Mic troll** → **Choose microphone device…** →
   pick **CABLE Input (VB-Audio Virtual Cable)**.
3. In the game / Discord, set the **microphone/input** to **CABLE Output
   (VB-Audio Virtual Cable)**.

> Important: for the troll to reach the game, pick the **CABLE Input** device in
> step 2 — not "System default output" (that plays to your speakers, which is only
> useful for testing). The app automatically grabs microphone permission the first
> time so Windows actually routes the audio to the cable; if you ever picked a
> device and later heard nothing, re-open the picker and choose the cable again.

Now on the iPad, under **🎤 Talk through the mic**, type a message (or tap a
preset), pick a voice, and **Send through mic** — it goes out on their voice chat.
You can also tap any uploaded sound → **Play through the mic**.

**Talk live with your own voice** (hold-to-talk): in the same section, press and
hold **🎙️ Hold to talk live** and speak — your iPad's microphone streams straight
out of the PC's mic in real time. The first time, the iPad switches to the PC's
secure (https) address so Safari will let it use your microphone:

- Tap through Safari's certificate warning once (**Show details → visit this
  website**) — it's your own PC, it just uses a self-signed certificate.
- Allow microphone access when asked, then hold the button and talk.
- Same Wi-Fi only (it's a direct connection to the PC).

> Tip: to hear the voice chat yourself too, Windows → Sound settings → the CABLE
> Output device → **Listen to this device**. And remember to switch the game's mic
> back to your real one afterwards. There's also a **System default output** option
> in the device picker if you want to test the mic trolls through your speakers
> first.

### Close their game from the iPad

Tap **Show open apps** and the **🧨 Close apps on the PC** section lists what your
friend currently has open (only things with a window). Tap one and it closes —
first politely, then forced if it ignores that (games often do) — so it reliably
goes down and just looks like it crashed. Windows' own critical system processes
are never listed and can't be closed, so you can't break the PC.

If the list is empty, tap **Show open apps** again once the game is actually open;
if it shows an error, it means Windows blocked the lookup (rare) — the message
says so.

## Use it from anywhere (optional sign-in, no QR)

Out of the box the iPad and PC must be on the **same Wi-Fi**. If you'd rather sign
in with an account and control the PC from **anywhere** (and skip the QR/code), set
up a free Firebase project — about 5 minutes:

1. Go to <https://console.firebase.google.com> → **Add project**.
2. **Build → Authentication → Get started** → enable **Email/Password**.
3. **Build → Firestore Database → Create database** (Production mode). In the
   **Rules** tab, paste the rules below and **Publish**.
4. **Project settings (gear) → General → Your apps →** the web icon `</>`.
   Register an app and copy the config values it shows.
5. **Authentication → Users → Add user**: create one login (email + password).
   You'll use that same login on the PC and the iPad — that's what pairs them.
6. In the Troll Remote folder, copy **`firebase-config.example.js`** to
   **`firebase-config.js`** and paste in your config values.
7. Restart Troll Remote. A **Sign in** box appears in the PC window and on the
   iPad page. Sign in on both with that one account — done. The PC remembers the
   sign-in between restarts.

When both devices are on the same Wi-Fi it still uses the fast direct connection
automatically; otherwise it relays through your Firebase project. The 6-letter
code keeps working too, as a fallback.

**Firestore security rules** (so only your account can see your data):

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{uid}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}
```

The values in `firebase-config.js` are **not secrets** (web apps ship them); your
data is protected by these rules plus your account password. `firebase-config.js`
is git-ignored so you won't commit it by accident.

**Do you even need this?** If you and the iPad are in the same house as the PC
(the usual case for trolling a friend), you're on the same Wi-Fi, so the plain
QR/code mode already works with zero setup — you can skip Firebase entirely. The
cloud is only for controlling the PC when you're **away** from its network.

> Heads up: the sign-up has to be done by you — a Firebase project is tied to your
> own Google account, so it's not something that can be set up on your behalf. The
> steps above are the whole thing (~5 min, free). The cloud relay code is wired up
> but, unlike the local Wi-Fi mode, it couldn't be tested against a live project
> from the build machine, so try it at home once. Firing effects, talking,
> closing apps and **uploading files (up to 20 MB) all work over the cloud** now;
> only the photo thumbnails in the file list need the same Wi-Fi.

## Keeping it updated

Every time it starts, Troll Remote quietly checks GitHub for changes. It never
blocks startup.

- **Installed with `git clone`:** it syncs to the **latest commit** on its branch
  automatically — so *every* push is picked up on the next start (no version
  number bump needed). It pulls the changes, reinstalls anything needed, and
  restarts, with a little "Updated" note. Your uploaded media, settings and local
  `firebase-config.js` are left untouched.
- **Installed from a ZIP:** it can't safely replace its own files, so instead it
  pops a tray notification when a new version is out — click it to open GitHub and
  download the update.

You can turn this off in the tray menu (**Update automatically on start**).

## Open the remote from anywhere (GitHub Pages)

You can host the **iPad remote page** at a permanent web address with GitHub
Pages, so you (or anyone you trust) can open it without the PC serving it — great
for adding it to your Home Screen.

1. In your fork/repo on GitHub: **Settings → Pages → Build and deployment →
   Source: GitHub Actions**. The included workflow publishes the page on every
   push; your link will be `https://<your-username>.github.io/Troll-app/`.
2. Because a secure `https` page can't talk to a plain `ws://` address on your
   local network, the hosted page works through the **cloud (Firebase)** only —
   so set up Firebase first (see above), then add your web-config values under
   **Settings → Secrets and variables → Actions → Variables** as
   `FIREBASE_API_KEY`, `FIREBASE_AUTH_DOMAIN`, `FIREBASE_PROJECT_ID`,
   `FIREBASE_STORAGE_BUCKET`, `FIREBASE_SENDER_ID`, `FIREBASE_APP_ID`.
3. Open the link on your iPad, sign in, and **Add to Home Screen**. It now works
   from anywhere.

If you're on the same Wi-Fi as the PC, you don't need any of this — just use the
QR code / local address as usual. (Uploads work over the cloud too, up to 20 MB;
only photo thumbnails in the file list need the same Wi-Fi.)

## Good to know

- **Scares not showing over the game?** Set the game's display mode to
  **Borderless** or **Windowed fullscreen**. Old-style "exclusive fullscreen" games
  draw over everything. Sounds always work either way.
- **Emergency stop** on the PC: `Ctrl+Alt+Shift+X`. Show the window again:
  `Ctrl+Alt+Shift+T`, or click the tray icon (bottom-right).
- **Starts with the PC**: toggle it in the window or the tray menu. When it
  auto-starts it opens straight to the tray, hidden.
- **Multiple monitors?** Right-click the tray icon → *Show scares on screen* to pick one.
- **Your own media:** drop files in the `media` folder, or upload them from the
  iPad. Images, mp3/wav/ogg/m4a sounds and mp4/webm videos are supported. (MP3s
  and videos now play reliably — they're served to the overlay over an internal
  channel instead of a raw file path, which some Windows setups refused.) If a
  file ever won't play, the iPad now shows the reason.
- **iPad can't connect?** Make sure both are on the same Wi-Fi (not a guest network),
  allow the app through the firewall, and try the other addresses listed under the QR code.
- Only someone with the 6-letter code (or, if you set up sign-in, your account)
  can control it. The code is saved in your user settings and stays the same
  between runs.
- The port is 4545 by default. Set the `TROLL_PORT` environment variable to change it.
